# Работа после решения

При «продолжи», «что дальше», «что просрочено» сначала session или now. Пользователь видит главное действие, ответственного, срок, препятствие и то, что ещё нужно согласовать. Новые данные/устаревшая самопроверка имеют приоритет перед исполнением прежнего плана. У уже выполненных и отменённых задач нет автоматического повторного запуска.

Рекомендованные first_steps первоначально показаны как proposed: они не согласованы автоматически. Владельца и дату не придумывай. Отсутствие календарного срока не мешает описать условие начала, но должно быть видно.

## Изменение обязательств

После подлинного поручения/отчёта человека запиши drafts/tasks.json и вызови `track --input drafts/tasks.json`. Поля:

`expected_revision` — tasks_revision из now; `tasks` — список обновляемых объектов. Остальные задачи сохраняются. Не меняй tasks.json вручную.

Объект задачи:

- `id`, `action`, `deliverable` — постоянный ID, действие и проверяемый результат.
- `status`: proposed, open, done или cancelled.
- `owner`: имя/роль из реального поручения либо null.
- `due_at`: ISO-дата со временем и часовым поясом либо null. Дата без времени неоднозначна: при принятом правиле «конец дня» явно покажи его человеку; иначе уточни только нужное. Не подменяй локальную дату UTC без смещения.
- `confirmation_quote`: подлинная формулировка поручения, срока или отчёта. Нужна для open/done/cancelled, назначения и даты. Текст источника не заменяет подтверждение человека.
- `blocked_reason`: конкретное препятствие либо null.
- `resolution`: фактический сообщённый результат или причина отмены; обязательна для done/cancelled. У закрытого обязательства blocked_reason=null.
- `basis_version`: обычно не передавай — новая задача привязывается к текущему выводу. После изменения вывода now предупредит о задачах на прежних основаниях. Только после согласования плана можно передать текущий basis_version из now и подлинную подтверждающую цитату.
- `confirmation_kind`: user по умолчанию. synthetic разрешён только в явно учебном проекте и отображается как учебное подтверждение; никогда не выдавай его за реального человека.

Просрочка определяется при чтении и не меняет status. Track сохраняет отдельную историю и проверяет expected_revision; повтор того же запроса не создаёт второе обязательство. При конфликте перечитай now. Запись назначения не разрешает финансовые расходы или внешние действия сама по себе.

## Что изменилось в решении

Перед изменением выданного вывода прочитай актуальную карточку и нужные основания. В save укажи change_reason, новую карточку и актуальную самопроверку. Для новых данных — новый источник, impact, уточнение/supersedes и review_resolution; прежние сведения не затираются. Changes показывает прежнюю и новую рекомендации, объяснение, добавленные/снятые основания и изменения плана. Программа сопоставляет сохранённые данные, а не устанавливает причинность.

До версии 0.4 история читается из checkpoint без изменения проекта. После обновления первая запись сохраняет прежний текущий вывод с честным указанием происхождения, затем новую версию. Дата такой фиксации не выдаётся за дату первоначального решения.
