# Короткий разбор и продолжение: 0.4

Проверка инструментов на знакомом учебном кейсе экспорта. Первоначальные входы — ../export-diagnosis/product.md и feedback.md. Исправление — [corrected-product.md](corrected-product.md). Все сведения, назначение «Учебный продакт» и цитата подтверждения вымышлены; в реальном проекте так записывать согласие человека нельзя.

1. Начат quick diagnosis. Preview вернул источники с локаторами; подготовлены три утверждения, короткая карточка и самопроверка. Первый читаемый результат: start → save → report. Отдельные analysis/research-plan/validation-plan не создавались. Автоматический технический след сохранён.
2. Через track записаны явно учебное обязательство с прошедшим сроком и отдельное предложение без владельца/даты. Просрочка не изменила status.
3. Новое учебное описание опровергло прежнюю применимость HTML-экспорта. Ingest/impact/save сохранили уточнение, новую самопроверку, объяснение пересмотра и вторую версию.
4. Now предлагает сверить прежние обязательства с новым выводом. Changes показывает «раньше / сейчас / почему», добавленные и снятые основания. Первую версию не переписали.

Это smoke-проверка разработчиком, не независимый LLM-прогон и не доказательство ускорения относительно замера 0.3. Вспомогательный скрипт дважды прерывался при чтении метаданных; тот же проект продолжен без повторного импорта. Ошибок CLI не было. Время первых CLI-вызовов после прерывания недоступно и не подменено нулём; стоимость/модель неизвестны. Ранее сохранённые исследования не менялись.

Для проверки пользователем: открыть папку агента, попросить новый короткий разбор по этим явно учебным материалам, затем дать исправленное описание. Реального ответственного/срок указывать только по фактическому поручению; демонстрационный сценарий не является поручением проводить исследование с людьми.
