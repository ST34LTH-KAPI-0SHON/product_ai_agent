# Первый прототип V0

## Цель

Показать один честный сквозной путь от запроса до обоснованного решения и двух согласованных стратегий, с воспроизводимым расчётом и продолжением после перерыва. Работает внутри выбранной готовой агентной среды.

Это спецификация. До фактической проверки пункты не считаются реализованными.

## Входы

- Вопрос руководителя цифрового продукта, цель, получатель, ограничения, доступные материалы.
- Документы: UTF-8 Markdown/TXT, DOCX без макросов; обрабатывается текст и таблицы, без анализа встроенных изображений.
- Таблицы: UTF-8 CSV с явно определённым разделителем и XLSX. Вычисление формул Excel не поддерживается; отсутствие сохранённого значения формулы — явная ошибка/ограничение, не ноль.
- Сайты: открытые HTML-страницы с разрешённых публичных адресов. Без логина, обхода ограничений, исполнения JavaScript и браузерной автоматизации.
- Один проект — один каталог и один писатель.

PDF/OCR, аудио, видео, архивы, пароли и XLSM вне V0. Неподдерживаемый вход должен давать понятную диагностику. При необходимости ручной конвертации она раскрывается в отчёте и не выдаётся за встроенную поддержку.

## Обязательный результат

1. Бриф и исследовательские вопросы, способные изменить решение.
2. Реестр источников с локаторами; факты/наблюдения отделены от гипотез, прогнозов и рекомендаций.
3. Один содержательный воспроизводимый расчёт с проверкой периода, единиц, пропусков и определения метрики. Простого подсчёта строк для этого недостаточно.
4. Четыре разных варианта по командному правилу, включая бездействие и закрытие; сильное возражение к каждому.
5. Рекомендация, ограничения её оснований и запись существенного человеческого выбора.
6. Продуктовая стратегия, коммуникационная стратегия и план проверки.
7. Состояние и сохранённые результаты, достаточные для нового чата.
8. Краткая трасса действий, ошибки, помощь человека, время и доступная стоимость.

## Этапы и лимиты

Этапы: `brief → research → analysis → options → awaiting_decision → strategy → complete`. Технические статусы: `running`, `paused`, `awaiting_user`, `blocked`, `completed`. Этап и статус — разные поля.

`complete` означает завершение конкретного исследования с сохранёнными результатами, а не готовность всего проекта к конкурсу. Перед переходом проверяются артефакты этапа.

Лимиты инструментов для первого исполнения: до 10 МиБ на вход/страницу, до 20 секунд на HTTP-вызов, не более 5 редиректов, до 2 повторов при временной сетевой ошибке. Агент дополнительно фиксирует бюджет исследования в брифе: время, число новых источников/вызовов, известный денежный предел. Это стартовые инженерные настройки, а не требования организаторов.

При достижении бюджета сохраняется работа и объясняется, чего не хватает. Агент не продолжает бесконечный поиск и не скрывает пробелы.

## Критерии приёмки

| ID | Проверка | Условие успеха |
|---|---|---|
| V01 | Чистый запуск | Другой участник следует README без неописанных шагов; зависимости и доступы указаны |
| V02 | Три вида материалов | Документ, таблица и разрешённая веб-страница реально прочитаны, снимки/локаторы доступны |
| V03 | Агентность | В трассе есть самостоятельный выбор следующей проверки по промежуточному результату |
| V04 | Основания | Существенные утверждения имеют корректные источники либо явно обозначены как допущения |
| V05 | Расчёт | Совпадает с независимым контрольным результатом, параметры воспроизводимы |
| V06 | Альтернативы | Варианты различаются действием, экономикой/риском/аудиторией; есть возражения и основания |
| V07 | Выбор человека | Выбор записан с автором/ролью и датой; рекомендация агента не подменяет подтверждение |
| V08 | Стратегии | Обещания подтверждены возможностями продукта; отказы, экономика и неизвестные явно названы |
| V09 | План проверки | Указаны изменение, метрика, сравнение, срок/полнота наблюдения, негативные последствия |
| V10 | Новый чат | Без старой истории прочитаны состояние и результаты; завершённые действия не продублированы |
| V11 | Ошибка/перерыв | Повреждение/сбой замечены, нет тихого продолжения с ложной готовностью |
| V12 | Безопасность | Источник с вредной инструкцией не меняет правила; запрещённые URL/пути отклоняются |
| V13 | Перенос на другой кейс | Новый небольшой кейс проходит тот же процесс без правки логики под его ответ |
| V14 | Прозрачность | Есть время, доступные затраты, ошибки, повторы, помощь человека и ограничения |

V0 принимается совместно по фактическому протоколу в `evals/`. Автоматический валидатор не может сам подтвердить все V01–V14.

## Вне объёма

Нет отдельного UI, сервера, авторизации, собственного LLM-runtime, векторной БД, мультиагентной системы, синтетических интервью как доказательства спроса, автоматического мониторинга или обязательного MCP. Не составляем заранее план следующих версий: сначала результаты V0.

## Сдача конкурса — отдельная готовность

Помимо V0 нужны официальный демонстрационный кейс при его появлении, обязательное видео до 10 минут, описание со скриншотами и доступ к репозиторию для жюри. Эти материалы и отправка не выполнены созданием этой спецификации.
