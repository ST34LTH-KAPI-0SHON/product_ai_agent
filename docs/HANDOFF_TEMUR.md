# Темур: передача технической работы V0

## Задача для тебя и твоей LLM

Реализовать локальные инструменты, на которые сможет опираться продуктовый агент в готовой среде. Контекст конкурса и проектные решения уже описаны в репозитории. Собственную модель, сервер, чат или автономный движок писать не нужно.

Если пользователь поручил начать разработку, после чтения документов переходи к реализации. Не ограничивайся планом и не проси заново пересказать обсуждение команды. Конкретный блокирующий вопрос задавай, продолжая независимые части.

## Прочитать

1. `AGENTS.md` и `docs/STATUS.md`.
2. `docs/CONTEST.md` — что сдаём и почему это папка агента.
3. `docs/PROTOTYPE_V0.md` и `docs/ARCHITECTURE.md`.
4. `docs/CONTRACTS.md` — интерфейсы, реестры и ошибки.
5. `instructions/entry.md` и `instructions/workflow.md` — как продуктовый агент будет пользоваться инструментами.

## Технический подход

Целевой интерфейс — Python CLI `python -m product_ai_agent ...`. Создай устанавливаемый пакет в `src/product_ai_agent/`, `pyproject.toml` и необходимые содержательные тесты. Точные зависимости выбери по задаче и зафиксируй; зависимости пока не установлены и не утверждены этим документом.

Предпочтение — минимальный понятный Python-код, UTF-8, относительные пути, стандартные форматы. Для DOCX/XLSX/HTML можно подключить профильные библиотеки; не писать собственный парсер этих форматов ради экономии нескольких зависимостей. Объясни их назначение и ограничения. LLM API-ключ backend-инструментам не нужен.

## Порядок B01–B07

### B01 — каркас и создание проекта

- Проверь реальное состояние: не перезаписывай существующую реализацию.
- Добавь пакет, CLI `init`, `status`, `validate` с честной текущей областью проверки.
- `init` создаёт структуру из архитектуры и состояние `brief/running`, пустые реестры и политику с закрытым сетевым доступом.
- Повторный `init` не затирает данные. Незавершённое создание обнаруживается.
- Опиши установку в чистое виртуальное окружение для реально проверенной системы.
- Проверь создание, повтор, путь с Unicode/пробелами, запрет выхода за рабочий каталог.

### B02 — локальные источники

- `ingest-file` для Markdown/TXT, DOCX, CSV/XLSX.
- Сохрани оригинал/снимок, SHA-256, формат, извлечённое представление и устойчивые локаторы.
- Повтор того же импорта с тем же содержимым не создаёт новый источник.
- Файлы не изменяются, формулы/макросы не исполняются. Неоднозначность CSV и отсутствие cached-значений XLSX не скрываются.
- Проверь многострочный CSV, таблицу DOCX, несколько листов XLSX, пустой/повреждённый/неподдерживаемый файл.

### B03 — сайты

- `ingest-url` работает только по политике проекта с разрешёнными точными URL.
- До соединения и при каждом редиректе проверь протокол, hostname, порт и публичный IP; адрес фактического соединения также не должен оказаться внутренним после DNS-подмены.
- Не обходи сетевые ограничения, логин, CAPTCHA и доступ к закрытым данным.
- Сохрани запрошенный и конечный URL, время, снимок HTML, текст, локаторы и предупреждения.
- Ограничь размер, время и повторы; соблюдай ограничения источника. Страница с требуемым JavaScript не считается успешно прочитанной, если вместо данных получен пустой каркас.
- Для автоматических тестов используй транспортную заглушку; реальный loopback в production-политике остаётся запрещён. Нужен также один разрешённый реальный сетевой smoke-check при доступном интернете.

### B04 — аналитика

- `profile-table`: строки, столбцы, типы, пропуски, предупреждения и видимые диапазоны дат при явном выборе поля.
- `aggregate`: ограниченная декларативная спецификация расчёта, без произвольного `eval`.
- Сохрани источник, лист/поля, фильтры, пропуски, единицы, период, результат и версию кода.
- Реализуй хотя бы один содержательный расчёт для кейса по согласованному определению тимлида. До согласования можно делать общую агрегацию; не подменяй ею готовую методику retention.
- Проверь итог на маленьком независимо рассчитанном примере, включая пропуски и неполный период.

### B05 — основания и продолжение

- `record-claim` проверяет поля и ссылки на источники/расчёты.
- `checkpoint` атомарно сохраняет ревизию и историю; защищает от перезаписи устаревшим состоянием.
- `resume` возвращает состояние и пути к необходимым материалам; сам не вызывает LLM.
- Операции имеют idempotency key и статусы; незавершённая операция восстанавливается по файлам, а не автоматически считается успешной.
- Проверяются восстановление после прерванной записи и повтор с тем же ключом. Не обещай exactly-once для внешних действий.
- Журнал решений хранит подтверждённый выбор пользователя; инструмент не генерирует его самостоятельно.

### B06 — валидатор

- Проверяй обязательные поля, ID, относительные пути, хеши, уникальность, ссылки, допустимые этапы и артефакты этапа.
- Проверяй, что `complete/completed` недоступен при незавершённых операциях, отсутствующем выборе или обязательных результатах.
- Ошибки должны быть локализованы и пригодны для исправления, stdout — структурированным.
- Не называй такую проверку доказательством истинности фактов или качества стратегии.

### B07 — интеграция

- Пройди с тимлидом V01–V14; обнови README под действительные команды и ограничения.
- Зафиксируй среду, версии, зависимости, доступы, время, расходы, ошибки и помощь человека.
- Проверь запуск на другом небольшом кейсе и продолжение в новом чате.
- Передай список оставшихся проблем. Не отмечай всю работу `done`, если прошёл только happy path.

## Формат отчёта LLM после рабочей сессии

1. Реализованные пункты и изменённые файлы.
2. Команды/процедуры проверок и результаты.
3. Известные ограничения и конкретные зависимости от тимлида.
4. Обновление `docs/STATUS.md` и следующий незавершённый пункт.

Не меняй исследовательский смысл метрик, не придумывай продуктовые факты и не публикуй скрытые данные ради успешной демонстрации.
