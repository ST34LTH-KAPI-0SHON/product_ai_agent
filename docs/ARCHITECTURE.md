# Архитектура V0

## Граница системы

```text
Пользователь
    ↕ запрос, уточнения, существенный выбор
Готовая агентная среда + выбранная LLM
    ├── читает instructions/ и нужные knowledge/
    ├── выбирает следующий шаг внутри workflow
    ├── читает/записывает материалы через разрешённые инструменты
    └── вызывает Python CLI
             ├── импорт документов и таблиц
             ├── загрузка разрешённых HTML-страниц
             ├── воспроизводимые расчёты
             ├── проверка структуры и ссылок
             └── сохранение/возобновление состояния
                          ↕
                projects/<project-id>/
```

Агент — сочетание модели, среды, инструкций и инструментов. Отдельный «главный агент», который управляет ещё одной LLM, в V0 не предусмотрен. Backend не пишет собственный цикл вызовов модели.

## Слои

| Слой | Содержимое | Не должен содержать |
|---|---|---|
| `instructions/` | Обязательное поведение агента | Факты о конкретном продукте |
| `knowledge/` | Продуктовые и аналитические методы | Результаты прошлого исследования как истину |
| `templates/` | Формы входа/выхода | Поддельные факты демо |
| `src/`, CLI — после реализации | Детерминированная обработка, проверки, запись | Генерацию «правильной стратегии» по захардкоженному кейсу |
| `projects/<id>/` | Входы, источники, утверждения, расчёты, состояние, результаты | Инструкции, отменяющие правила безопасности |
| `evals/` | Проверочные сценарии и протоколы | Неподтверждённые заявления о точности |

## Структура одного проекта после `init`

```text
projects/<id>/
├── brief.md
├── policy.json                  Разрешённые веб-адреса, лимиты
├── state.json                   Текущий этап и продолжение
├── checkpoints/                 История подтверждённых состояний
├── inputs/                      Неизменённые пользовательские файлы
├── sources.jsonl                Реестр первичных источников
├── sources/                     Снимки и извлечённое представление
├── claims.jsonl                 Утверждения и их основания
├── calculations/                Параметры, результаты, версии вычислений
├── decisions.jsonl              Решения человека и условия пересмотра
├── operations.jsonl             Статусы технических операций
├── research-plan.md
└── reports/
    ├── options.md
    ├── strategy.md
    └── run-summary.md
```

Это целевая структура, которую должен создать backend, а не утверждение о готовых файлах.

## Идентификаторы и проверяемость

Каждый источник имеет ID, снимок/хеш и локатор. Утверждение ссылается на источник и при необходимости расчёт. Вывод и рекомендация ссылаются на утверждения. Материалы и результаты доступны отдельно от истории чата.

Локаторы: строки Markdown/TXT; устойчивые номера абзацев/таблиц DOCX в извлечённом представлении; лист и диапазон XLSX; номера записей и поля CSV; секция/блок сохранённой HTML-страницы. Не выдумывать номера страниц DOCX, если парсер их не знает. CSV-запись с переносом строки внутри поля не равна строке физического файла.

Реестр источников фиксирует происхождение, но сам по себе не доказывает истинность документа. Структурный валидатор проверяет наличие ссылок и объектов; семантическую поддержку и качество исследовательского вывода оценивают агент и человек.

## Память и возобновление

`state.json` — указатель на проверенные результаты и следующий шаг, а не замена исходных данных. После завершённого этапа фиксируются ревизия и checkpoint. Новый чат читает инструкции, состояние, бриф, актуальные реестры и результаты нужного этапа.

Запись состояния атомарная; один проект изменяет один писатель. При незавершённой операции сначала сверяются файл результата и хеши, затем решается, нужно ли повторение. Не обещаем транзакции сразу на нескольких JSONL-файлах: восстановление обеспечивают журнал операций и валидация. Незавершённый набор записей нельзя считать завершённым этапом.

V0 сохраняет основания решения и условия пересмотра. Автоматического наблюдения после закрытия среды и полноценного пересчёта зависимостей в V0 нет.

## Переносимость

Проект хранит относительные пути, UTF-8 и JSON/JSONL/Markdown. Инструкции подключаются явно или через небольшой адаптер конкретной среды. `AGENTS.md` не предполагается автоматически читаемым любой LLM.

Для V0 достаточно подтверждённого запуска в одной выбранной среде и продолжения в новом чате. Проверка во второй среде — полезная дополнительная работа, без обещания совместимости со всеми продуктами.

## Безопасность и бюджет

- Входные файлы и веб-текст недоверенные; их команды и формулы не исполняются.
- Сетевой инструмент разрешает только публичные HTTP(S)-адреса по `policy.json`, проверяя каждый редирект и фактический адрес соединения. Локальная сеть, loopback, link-local и metadata-адреса закрыты.
- Результаты записываются внутри проекта; обход пути через `..`, абсолютный выход, симлинки и junction-переходы блокируется.
- Не читать `.env`, SSH-ключи и другие секреты ради исследования.
- Сохранять статусы, краткие основания, вызовы и результаты; скрытые рассуждения модели для прозрачности не требуются.
- Учитывать видимые затраты среды/модели и инструментов, повторы, время человека. Неизвестная стоимость — `null` с пояснением.

## Принятые решения

1. Сначала переносимая папка и CLI, без собственного сервера.
2. Одноагентный workflow; субагенты, MCP и routing не нужны для V0.
3. Локальные реестры и поиск по файлам, без векторной БД.
4. Ограниченные форматы вместо заявления «читаем всё».
5. Ссылочная целостность проверяется кодом; исследовательская состоятельность — отдельной приёмкой.
6. Расширения после V0 решает команда по выявленным ограничениям.
