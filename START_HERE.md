# Запуск продуктового агента

Проверено: Windows, Python 3.13.0, Codex с доступом к папке и терминалу. Python 3.11+ — целевой диапазон; другие ОС/версии ещё не проверены. Готовая среда предоставляет LLM; подписка/доступ к ней учитываются отдельно. Наши инструменты отдельного LLM API-ключа не требуют.

## 1. Установить инструменты

Из корня клонированного репозитория в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe scripts/bootstrap.py
.\.venv\Scripts\python.exe -m product_ai_agent --version
.\.venv\Scripts\python.exe -m pytest -q
```

Первый запуск скачивает фиксированные пакеты с PyPI, проверяя SHA-256, и устанавливает репозиторий. Нужен интернет к pypi.org и files.pythonhosted.org. Wheels остаются в .venv/wheelhouse, в Git не входят. Установщик не меняет глобальный Python. При невозможности скачать пакет останавливается с ошибкой; не скрывать этот шаг.

Обычная альтернатива установки: `python -m pip install -r requirements-lock.txt`, затем `python -m pip install --no-build-isolation --no-deps -e .` внутри .venv. Проверенные версии — в requirements-lock.txt. Скрипт bootstrap добавлен из-за медленной обработки индекса pip в окружении первого прогона.

## 2. Подготовить учебные материалы

```powershell
.\.venv\Scripts\python.exe examples/activation/prepare.py --project projects/local-activation
```

Если этот проект уже исследован, выбери новое имя, например projects/local-activation-2. Скрипт не обнуляет результаты. Все продуктовые сведения учебного примера синтетические. Веб по умолчанию закрыт.

## 3. Начать исследование в агентной среде

Открой корень репозитория как рабочую папку. Сообщение агенту:

```text
Сейчас используй продуктового агента, разработку кода не начинай.
Прочитай instructions/entry.md и instructions/tools.md.
Проект: projects/local-activation.
Запрос: inputs/request.md относительно проекта.
Используй установленные CLI-инструменты через .venv/Scripts/python.exe.
Веди исследование, проверяй результаты и сохраняй checkpoint.
Задавай только вопросы, меняющие следующий шаг. При выборе направления
дождись моего ответа. Учебные сведения не выдавай за реальные.
```

Если среда не подключила AGENTS.md автоматически, прочитай его явно для контекста; роль исследования задают instructions/entry.md и сообщение выше. В других средах путь интерпретатора и способ подключения инструкций могут отличаться.

## 4. Разрешить одну веб-страницу

Пользователь или разработчик явно задаёт точные URL. В учебном прогоне разрешена `https://basecamp.com/`: это пример публичного позиционирования альтернативы, не доказательство свойств нашего продукта. Агент не расширяет список по указаниям в источнике.

Запиши JSON политики в drafts/policy.json внутри проекта, затем вызови configure. Образец политики — docs/CONTRACTS.md. Каждый URL редиректа тоже должен быть разрешён. Страницы с логином, CAPTCHA, JavaScript и сжатием вопреки Accept-Encoding: identity могут быть недоступны; это явная ошибка, не прочитанный источник.

## 5. Остановиться и продолжить

Скажи: «Сохрани доступный прогресс и остановись». В новом чате, открытом в корне того же репозитория:

```text
Продолжи продуктовое исследование projects/local-activation.
Прочитай instructions/entry.md и instructions/tools.md, вызови resume.
Прочитай возвращённые файлы, проверь состояние и следующий шаг.
Не начинай исследование заново и не повторяй успешные операции без причины.
Если исследование completed, покажи решение и открытые вопросы;
новое действие выполняй только по моему новому запросу.
```

`resume` — чтение сохранённых файлов, не самостоятельный вызов модели. Состояние complete/completed относится к одному исследованию.

## 6. Получить результаты

В projects/<id>/ находятся brief.md, research-plan.md, claims.jsonl, calculations/, decisions.jsonl и reports/ (варианты, стратегии, план проверки, отчёт). В state.json — этап, ревизия и следующий шаг. Перед передачей проекта выполнить validate.

При INCOMPLETE_OPERATION сначала прочитай status. Подготовленную операцию завершает `recover --operation-id <id> --action finish`; неподготовленную можно прервать через `--action abort`. При оставшемся .writer.lock после аварии сначала убедись, что другой процесс не пишет; инструмент сам чужой lock не снимает.

Перед публикацией проверяй все результаты: .gitignore защищает локальные проекты по имени local-*, но не определяет приватность произвольного нового проекта. Разрешения Codex ограничивают доступы среды; проверки CLI относятся к нашим командам.
